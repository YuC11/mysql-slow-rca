# MySQL 变慢诊断项目：工具化升级 + 案例补全 + 结束清理脚本

目标：从"85 分演示手册"升级为"企业级完整复刻"——把手册判断逻辑变成可执行工具，补齐四个企业高频根因的实跑演示，新增结束清理脚本回收演示脏数据，修复全部失实表述并重建实跑证据链。**不新增第六类，不加监控栈。**

## 实施步骤

### 1. 基础修复（杂项与可移植性）
- `demo/conf/my.cnf`：删除 `open_files_limit=4096`（mysqld 会自动上调，是手册 §8.1 数值矛盾的来源）；顶部注释 "512MB" → "1G"
- README 与手册 §1.1：`--cpus=2` 的注释 "1C1G" → "2核1G"
- 删除根目录与 `demo/` 下 `.DS_Store`；新增 `.gitignore`；`git init` 并提交现状
- `demo/scripts/lib.sh` 凭据改造：新增 600 权限的 `.my-user1.cnf`/`.my-root.cnf`，`MYSQL`/`ROOT` 改用 `--defaults-extra-file`，消除明文密码与 Warning 刷屏；case3/case4 里 3 处 `mysqlslap -ppasswd1` 同步修改

### 2. 新增 `demo/scripts/99-down.sh`——结束清理脚本（本次新增的核心交付物）
与 `00-up.sh` 成对，两种力度：

**默认（轻量清理）**：保留容器与业务数据，清除所有演示残留——
- 会话级：KILL 所有 user1 连接（case3 FIFO 空闲连接残留）
- 对象级：`DROP` case5 的 `cfg_test`/`p_insert`、新案例的 `demo_stats`/`demo_bloat`、`repltest` 库与 `'repl'@'%'` 用户；`DROP INDEX` case1 加的 `idx_sku`/`idx_created_cust_amount`；`DROP COLUMN` case2 残留的 `tmp_demo_col`（按 information_schema 探测，存在才删，与现有脚本容错风格一致）
- 数据级：`UPDATE inventory JOIN products` 恢复库存、恢复 orders id=1 的 remark 与 inventory_log 的 change_qty、删除间隙锁演示可能插入的 `promo_code id=1005`
- 参数级：`RESET PERSIST`（清 case5 的 `SET PERSIST max_connections`）；恢复 `sync_binlog=1`/`innodb_flush_log_at_trx_commit=1`/buffer pool 128M/`general_log=OFF`
- 状态级：清空 digest 表、FLUSH STATUS、按 lib.sh 的 reset_slowlog 模式清慢日志
- 复制级：从库可达则 `STOP REPLICA; RESET REPLICA ALL`
- 文件级：清理 `/tmp/case2_* /tmp/case3_* /tmp/case4_*`；保留 `case1~5.out` 证据文件

**`--all`（彻底清理）**：`docker rm -f mysql-demo mysql-replica` + `docker volume rm mysql-demo-data` + 清空 `demo/logs/` 与 `demo/baselines/` + /tmp 残留，回到未初始化状态，打印 `00-up.sh` 重建提示

### 3. 新增 `demo/scripts/diagnose.sh`——自动分流诊断
手册 §2 决策树脚本化，一键采集 + 判定 + 归类（`> demo/logs/diagnose.out`）：
- 五黄金信号逐项 PASS/WARN/FAIL（阈值取自手册 §2.3/§2.6）：Threads_running vs 核数×2、连接数 vs 上限 80%、Slow_queries、行锁等待、命中率（<99% WARN、<97% FAIL，注明累计值口径）、磁盘临时表
- 连接分布（Sleep 占比）、digest Top10（无索引/磁盘临时表逐条标注）、长事务（>60s FAIL）、锁等待关系、复制状态（有从库才采集）
- 末尾自动结论：按决策树输出"优先排查案例X（证据：…）"，保留因果链提醒（连接打满时回头查慢 SQL）
- 纯 bash + mysql，与 lib.sh 风格一致

### 4. 新增 `demo/scripts/baseline.sh`——基线快照
`save [tag]` 采集状态计数器/digest Top10/各表 DATA_FREE/关键配置 → `demo/baselines/<tag>.txt`；`diff <t1> [t2]` 输出增量 + 按 Uptime 差值算每分钟速率。

### 5. `99-health-check.sql` 升级
第 1 节五个黄金信号增加 SQL 内 CASE WHEN 的"判定"列，保留原始值列。

### 6. 四个新案例（并入现有脚本，不开第六类）
| 新演示 | 并入 | 确定性要点 |
|---|---|---|
| 隐式类型转换 | case1 第 11 节 | `order_no=数字`（VARCHAR vs 数字常量），EXPLAIN + SHOW WARNINGS 看隐式 CAST，修复=显式类型匹配 |
| 统计过期→计划漂移 | case1 第 12 节 | 专用表 `STATS_AUTO_RECALC=0`：ANALYZE 后计划正确 → 大 DELETE+INSERT 使统计过期 → 优化器选错 → 再 ANALYZE 翻回，前后对比 |
